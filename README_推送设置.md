# ETF信号助手 - 微信定时推送设置说明

## 文件说明

* `daily_etf_push.py` ：分析 + 推送主脚本

* `daily_push.yml` ：GitHub Actions 定时配置

## 设置步骤

### 1. 把文件放到你的 GitHub 仓库

建议结构：

```
你的仓库/
├── etf_signal_app.py          # 网页版（已有）
├── requirements.txt
├── daily_etf_push.py          # 新增
└── .github/
    └── workflows/
        └── daily_push.yml     # 新增
```

### 2. 添加 SendKey 到 GitHub Secrets（重要！）

1. 打开你的仓库 → Settings → Secrets and variables → Actions
2. 点击 New repository secret
3. Name 填写：`SERVERCHAN_SENDKEY`
4. Secret 填写：你的 SendKey（SCT开头的那串）
5. 点击 Add secret

### 3. 启用 GitHub Actions

如果是新仓库，可能需要在 Actions 页面点击启用。

### 4. 测试

在仓库的 Actions 页面，找到 “Daily ETF Signal Push”，点击 “Run workflow” 手动运行一次，检查微信是否收到消息。

### 推送时间（工作日）

* 盘中 11:00–11:30 窗口内

* 盘后 15:20–15:50 窗口内
  （均为北京时间）

原来还有一条盘前 08:50。删掉它不是为省钱：盘前拿不到当日 K 线，它的数据基准和结论
跟昨晚盘后那条逐字相同，只是把同一句话再说一遍，却占掉 Server酱每天 5 条额度里的 1 条。
现在一天两条，腾出的额度留给真正需要重试的时候。

### 5. 首次部署后不用做任何手动初始化

（这一节是给“直接替换文件”的人看的，看完可以删）

不用手动跑 `--backfill-prem`。盘后那条推送在写台账前会检查「哪些标的还没有溢价基准」，
缺的那几只自动去拉 90 天净值历史，补进 `signals.json` 的 `prem_hist` 字段；建好之后
`ensure_prem_history()` 直接返回，一次请求都不再发。所以第一次盘后推送会比平时慢
1–2 分钟，之后恢复正常。

`signals.json` 里旧的 `c` 字段（当日收盘，已不再写入）、新加的 `sig_date`、`gate` 和 `prem_hist`
同时存在是正常的，读的时候会忽略不认识的字段。不懂 JSON 结构的话不要手动编辑它——
台账只会在盘后那条 workflow 里被覆盖写，手改很容易把整个文件写坏导致停止累积。

### 场外基金用的是累计净值

270044、270023 的指标现在算在**累计净值**上，不是天天基金里那个单位净值。单位净值每遇分红会
凭空掉一笔：270044 每季度分一次（1/4/7/10 月），每次约占净值 0.85%，而它平时一天只动万分之几，
等于一根 10\~30 倍于平时的假暴跌。累计净值已经把分红加回去，是唯一一条没有台阶的序列。

2026-10-30 生效。直接后果：10-19 那次分红把 270044 的 RSI 从 86.5 压到了 47.4，现在推送给的是
86.5。app 详情页那个数字也会变成累计净值（1.2140 → 1.7158），标签已跟着改成「累计净值」，
它不是你账户里每份值多少钱。溢价率仍然用单位净值（场内价格对着每份净值算，跟分红无关）。

### 溢价：两个数分开看（2026-11-06 改）

行里现在长这样：`溢价重 18.1%(11-04) · 偏+6.5pp · 趋势内·买入成本高`

* **`溢价重 18.1%`**：绝对值，回答「每份多付几个点」。8% 标「高」、12% 标「重」，
  和它自己过去怎么走无关，也不预测方向——额度受限的跨境品种可以长期维持高溢价，
  所以 159941 几乎天天带「重」，这是事实不是报警。
* **`偏+6.5pp`**：相对本品种最近 60 天中位数的偏离，回答「今天反不反常」。
  +4pp 显示、+7pp 加 ⚠。**没有基准就不出这个数**，不再退回绝对阈值——
  那会把两件事又混成一把尺子。

改的原因：上一版只有一个相对数，`prem_flag` 的 `"warn"` 档虽然算出来了但没有任何展示路径
（三个调用点都只判 `"heavy"`），而 heavy 线又被自身中位数抬高，两档同时失效。

### 变化层（2026-11-06 加）

正文最前面多一节 `🔀 较上一条（MM-DD 收盘）`，只印和上一个盘后快照的差异：

* 长期状态翻转（`长期↓ → 长期↑`）——长期↓ 是排除器，它一翻，可买集合就变了
* 新触发「不宜加仓」
* 新增金叉/死叉（盘中触发会标「未收盘」）
* 溢价变动 ≥ 2pp，带净值日（`14.2%(11-03) → 15.6%(11-04)`），
  避免把「换了个净值日」读成溢价真的掉了几个点

没有变化就印一行「无状态变化」。这一节必须在 `record_ledger` **之前**计算，
否则台账已被当天覆盖，delta 恒为 0。台账里新增 `prem_date` 字段记录溢价对应的净值日，
旧记录没有这个字段时只是不显示日期，不影响结算。

### 行尾的四格结论（2026-11-06 加）

每只 ETF 的行尾会追加它当前落在 2×2 里的哪一格：

|  | 溢价正常（<12%） | 溢价重（≥12%） |
| --- | --- | --- |
| 长期↑ | 趋势内·成本正常 | 趋势内·买入成本高 |
| 长期↓ | 趋势走弱·成本正常 | 既贵又逆风 |

场外基金（270044 / 270023）不做长期判定、也没有溢价，所以不追加这一项。
四格不是评分：两件事各说各的，没有权重，也没有「多少分以上买」。文案只存在于
`MATRIX_CELLS` 这一处，推送行尾和 app 详情页的四格图共用，避免两边措辞分叉。


### app 图表（2026-11-06 加）

详情页原来的 `st.line_chart` 换成 Plotly 三栏图，默认 250 个交易日（可切 120/400）：

* **主图**：收盘（场外为累计净值）与 MA20/60/200；绿/红底色是 `long_state_series` 在全序列上
  递推后切窗口得到的长期↑/长期↓，无底色段是 MA200 未暖机；▲/▼ 是 `cross_points` 找出的全部
  交叉，和推送的 `find_last_cross` 用同一判定式。
* **RSI**：只画线并标注「仅参考」——回测里按 RSI 拦信号会让结果更差，它不参与判定。
* **溢价**：台账 `prem_hist` 曲线 + 最近 60 个观测的中位线 + 4pp/7pp 偏离线，当前点按净值日标注。
  中位线与「偏+Xpp」同源（都走 `prem_history`），不会出现图上一条基准、行里另一条基准。

四格状态（长期方向 × 绝对溢价）只把两个事实并排放，**没有加权评分**：金叉与趋势方向都不预测
涨跌，有依据的只有买入成本和「长期↓ 排除」。做成分数会诱导「多少分以上买」，等于给未验证的
权重背书。

依赖新增 `plotly`，只写进 `requirements.txt`；不要加到 workflow 的 pip 清单（推送脚本不画图）。
推送端仍是纯文本，不生成图片。

### 「不宜加仓」标记（2026-11-02 加，11-06 改）

只有同时满足下面两条，行尾才会出现 **不宜加仓**：

1. 长期↓（价格在 MA200 下方，带缓冲带）
2. **绝对溢价 ≥ 12%**（11-06 改：原来用的是「高出本品种最近 60 天中位 7 个百分点」）

为什么改：相对基准回答的是「今天是否反常」，不是「买得贵不贵」。159941 的中位约 11.8%，
重警线因此被抬到 18.8%，而它 90 天里的最高溢价才 18.85%——用相对尺子做成本判断，
等于把最贵的那只永久豁免。

单独一条都不标：长期↓ 拿来判方向已被证伪（30 只 22260 个观测，超额≈0），溢价高单独看只是成本
描述。两条叠起来说的是当下已经存在的一件事——此刻用市价买入，既站在趋势的反方向上，又在为
该品种历史上少见的偏离付钱。底部会跟着出现「当期既贵又逆风」的解释，不触发时那行根本不出现；
文案只写已发生的事实，不用「风险较高」「建议观望」这类会被二次解读的词。

触发情况会写进台账（`signals.json` 里每条多一个 `gate`：1 或 0），但**不进胜率结算**——它只是存
下「哪天触发过」供以后统计频率和回看表现，拿它算胜率等于把成本约束当成方向判断。注意 2026-11-02
之前的旧记录没有这个字段（那时约束还不存在）。主标签（金叉/死叉/持有）不会被覆盖：它们是「今天
发生了什么」的事件记录，和「现在买得贵」是两回事，同时出现不是矛盾；而且金叉已被证明不预测方向，
「逆风中的金叉」恰恰是最需要同时看到这两个信息的那一档。

2026-11-02 当天 14 只全部不满足（长期↓ 的那 9 只溢价都在 ±1.5% 内），所以这条是放着等触发的，
不会让今晚的推送和之前不一样。

### 东财熔断（2026-11-02 加）

东财整条线挂掉时（10-30 实测过全天 14 只全失败），每只要在一个「2 个分支 × 2 次重试 × 1 秒休眠」
上白等约 4 秒，14 只接近一分钟。现在连续 5 只拿不到数据就熔断，本轮剩余场内标的直接走腾讯兜底，
底部「数据源」那行会补一句跳过了几只——不注明的话读者分不清「东财逐只失败」和「我们主动跳过」。

阈值定 5 而不是 3：11-02 出现过「14 只里 4 只失败、其余东财正常」的间歇抽风，太早熔断会把还能用的
东财换成价格只有 3 位小数的腾讯（实测会让 RSI 有小但真实的偏差）。成功一次就把连续失败归零，所以
间歇抽风不会累积成熔断。**场外基金 270044/270023 不参与熔断**：它们只有东财一条路、没有备用源，
跟着跳过的后果是债市晴雨表整节从推送里消失，那比慢 40 秒严重得多。app 每轮取数开头会把熔断状态
归零——它是长驻进程，一次误熔断就会永远只走腾讯。

### 月度滚动体检（2026-11-06 加）

台账记的是「发生过什么」，这张月报回答另一个问题：**这套规则最近还灵吗。**

触发挂在盘后那条上（每月第一条盘后推送顺带跑，`--if-due` 判断当月报告在不在），不另开定时器——
GitHub 的 schedule 对本仓库本来就不注册，外部定时器只驱动现在这两个窗口。生成后有两个落点：

* 微信单独一条 `ETF信号助手·月度体检·YYYY-MM`（结论段，5 行左右）
* 仓库 `review/review-YYYY-MM.md`（含明细表和口径说明，跟台账一起提交）

它数的是 6 条规则在最近 12 个月的表现：长期↑、长期↓、金叉、死叉、溢价≥12%、闸门。每条给 5/10/20 日
的「条件内平均收益 − 同期同池无条件收益」，20 日那列带 t 值。

三个不能省的约束，否则结论会骗人：

* **基准必须在同一窗口内重算**。跨年比较会把牛熊差当成规则能力——2024 年整年上涨，任何条件都好看。
* **t 值用不重叠子样本**。相邻 20 日窗口共享 19 天，拿全部日观测算 t 会把显著性吹大近 20 倍。
* **门槛是 |t|≥3 而不是 2**。一次同时检验 6 条规则，5% 双侧下至少一次 |t|>2 的概率约 26%；按 Bonferroni
  压到 0.05/6 对应 |t|≈2.9。有效样本 <12 一律写「样本不足」。

低于门槛只写「未检测到差异」，不写「无效」——这两件事不同：前者是这窗口里分不出来，后者是被证伪
（金叉/死叉那种「30 只 22260 个观测、超额≈0」才算证伪）。同理，**正向也不立刻改参数**：连续两个月
同向、幅度大于噪声才动，一次只动一条，改完记进本文件的证据清单。

溢价那两条规则依赖台账回填的溢价历史，月报会临时回填 252 天（只写内存，不碰 `signals.json`），
所以它的样本仍比另外四条短，n 会明显偏小。

手动跑：`python monthly_review.py --months 12`（只打印）；加 `--save` 写 `review/`，加 `--notify` 推一条。
