# ETF信号助手 - 微信定时推送设置说明

## 文件说明

* `daily_etf_push.py` ：分析 + 推送主脚本

* `daily_push.yml` ：GitHub Actions 定时配置

## 设置步骤

### 1. 把文件放到你的 GitHub 仓库

建议结构：

```
你的仓库/
├── etf_signal_app.py          # 网页版（已有）
├── requirements.txt
├── daily_etf_push.py          # 新增
└── .github/
    └── workflows/
        └── daily_push.yml     # 新增
```

### 2. 添加 SendKey 到 GitHub Secrets（重要！）

1. 打开你的仓库 → Settings → Secrets and variables → Actions
2. 点击 New repository secret
3. Name 填写：`SERVERCHAN_SENDKEY`
4. Secret 填写：你的 SendKey（SCT开头的那串）
5. 点击 Add secret

### 3. 启用 GitHub Actions

如果是新仓库，可能需要在 Actions 页面点击启用。

### 4. 测试

在仓库的 Actions 页面，找到 “Daily ETF Signal Push”，点击 “Run workflow” 手动运行一次，检查微信是否收到消息。

### 推送时间（工作日）

* 盘中 11:00–11:30 窗口内

* 盘后 15:20–15:50 窗口内
  （均为北京时间）

原来还有一条盘前 08:50。删掉它不是为省钱：盘前拿不到当日 K 线，它的数据基准和结论
跟昨晚盘后那条逐字相同，只是把同一句话再说一遍，却占掉 Server酱每天 5 条额度里的 1 条。
现在一天两条，腾出的额度留给真正需要重试的时候。

### 5. 首次部署后不用做任何手动初始化

（这一节是给“直接替换文件”的人看的，看完可以删）

不用手动跑 `--backfill-prem`。盘后那条推送在写台账前会检查「哪些标的还没有溢价基准」，
缺的那几只自动去拉 90 天净值历史，补进 `signals.json` 的 `prem_hist` 字段；建好之后
`ensure_prem_history()` 直接返回，一次请求都不再发。所以第一次盘后推送会比平时慢
1–2 分钟，之后恢复正常。

`signals.json` 里旧的 `c` 字段（当日收盘，已不再写入）、新加的 `sig_date`、`gate` 和 `prem_hist`
同时存在是正常的，读的时候会忽略不认识的字段。不懂 JSON 结构的话不要手动编辑它——
台账只会在盘后那条 workflow 里被覆盖写，手改很容易把整个文件写坏导致停止累积。

### 场外基金用的是累计净值

270044、270023 的指标现在算在**累计净值**上，不是天天基金里那个单位净值。单位净值每遇分红会
凭空掉一笔：270044 每季度分一次（1/4/7/10 月），每次约占净值 0.85%，而它平时一天只动万分之几，
等于一根 10\~30 倍于平时的假暴跌。累计净值已经把分红加回去，是唯一一条没有台阶的序列。

2026-10-30 生效。直接后果：10-19 那次分红把 270044 的 RSI 从 86.5 压到了 47.4，现在推送给的是
86.5。app 详情页那个数字也会变成累计净值（1.2140 → 1.7158），标签已跟着改成「累计净值」，
它不是你账户里每份值多少钱。溢价率仍然用单位净值（场内价格对着每份净值算，跟分红无关）。

### 「不宜加仓」标记（2026-11-02 加）

只有同时满足下面两条，行尾才会出现 **不宜加仓**：

1. 长期↓（价格在 MA200 下方，带缓冲带）
2. 溢价到本品种的重警线——有台账基准时是「高出最近 60 天中位 7 个百分点」，没基准时是绝对 12%

单独一条都不标：长期↓ 拿来判方向已被证伪（30 只 22260 个观测，超额≈0），溢价高单独看只是成本
描述。两条叠起来说的是当下已经存在的一件事——此刻用市价买入，既站在趋势的反方向上，又在为
该品种历史上少见的偏离付钱。底部会跟着出现「当期既贵又逆风」的解释，不触发时那行根本不出现；
文案只写已发生的事实，不用「风险较高」「建议观望」这类会被二次解读的词。

触发情况会写进台账（`signals.json` 里每条多一个 `gate`：1 或 0），但**不进胜率结算**——它只是存
下「哪天触发过」供以后统计频率和回看表现，拿它算胜率等于把成本约束当成方向判断。注意 2026-11-02
之前的旧记录没有这个字段（那时约束还不存在）。主标签（金叉/死叉/持有）不会被覆盖：它们是「今天
发生了什么」的事件记录，和「现在买得贵」是两回事，同时出现不是矛盾；而且金叉已被证明不预测方向，
「逆风中的金叉」恰恰是最需要同时看到这两个信息的那一档。

2026-11-02 当天 14 只全部不满足（长期↓ 的那 9 只溢价都在 ±1.5% 内），所以这条是放着等触发的，
不会让今晚的推送和之前不一样。

### 东财熔断（2026-11-02 加）

东财整条线挂掉时（10-30 实测过全天 14 只全失败），每只要在一个「2 个分支 × 2 次重试 × 1 秒休眠」
上白等约 4 秒，14 只接近一分钟。现在连续 5 只拿不到数据就熔断，本轮剩余场内标的直接走腾讯兜底，
底部「数据源」那行会补一句跳过了几只——不注明的话读者分不清「东财逐只失败」和「我们主动跳过」。

阈值定 5 而不是 3：11-02 出现过「14 只里 4 只失败、其余东财正常」的间歇抽风，太早熔断会把还能用的
东财换成价格只有 3 位小数的腾讯（实测会让 RSI 有小但真实的偏差）。成功一次就把连续失败归零，所以
间歇抽风不会累积成熔断。**场外基金 270044/270023 不参与熔断**：它们只有东财一条路、没有备用源，
跟着跳过的后果是债市晴雨表整节从推送里消失，那比慢 40 秒严重得多。app 每轮取数开头会把熔断状态
归零——它是长驻进程，一次误熔断就会永远只走腾讯。
